# Скіли Feededify: інструкція для адміна

Канонічна версія англійською: [README.md](README.md).

Плагін **`feededify`** містить два скіли:

| Скіл | Що робить |
|---|---|
| `feed-prompt-audit` | Аудит optimized feed за вихідними товарами: профілює дані, перевіряє наявні промпти й радить, які поля варто оптимізувати, з ризиками та чернетками промптів. Нічого не зберігає. |
| `optimized-field-prompt` | Пише й виправляє промпти полів (Products → Edit prompts). Зазвичай ти вставляєш результат у Prompt Studio сам. З підключеним admin MCP вміє ще й **авто-тюн** (див. нижче). |

Скіли працюють разом: аудит використовує скрипти й правила другого скіла.

## Встановлення (один раз)

**Claude Code.** Виконай дві команди всередині Claude Code і перезапусти його:

```text
/plugin marketplace add feededify-tech/feededify-for-agent
/plugin install feededify@feededify-for-agent
```

Якщо перша команда падає з помилкою SSH, використай повну адресу:
`/plugin marketplace add https://github.com/feededify-tech/feededify-for-agent.git`.

- **Перевірка:** спитай агента «які в тебе скіли feededify?». У відповіді мають бути `feededify:optimized-field-prompt` і `feededify:feed-prompt-audit`.
- **Автооновлення:** `/plugin` → Marketplaces → `feededify-for-agent` → Enable auto-update.

**Codex.** Завантаж репо (Code → Download ZIP) і скопіюй **обидві** теки, `skills/optimized-field-prompt` і `skills/feed-prompt-audit`, поруч у `~/.agents/skills/` (у старіших версіях `~/.codex/skills/`). Аудит використовує скрипти другого скіла, тому одна тека не працюватиме.

**claude.ai.** Запакуй кожну з двох тек у zip і завантаж у Settings → Customize → Skills. Без admin MCP скіли працюють у ручному режимі. Завантажуй **обидва** скіли: якщо аудит там не знайде `../optimized-field-prompt/scripts`, профіль і лінт він зробить вручну.

Node 18+ бажаний (агент ним перевіряє промпти й профілює фіди), але не обов'язковий.

## Підключення Feededify admin MCP

Разом із плагіном ставиться файл `.mcp.json`, який реєструє MCP-сервер `feededify-admin`
(`https://mcp.feededify.app/mcp`).

- **Перше використання:** Claude Code відкриє браузер, увійди своїм адмінським акаунтом Feededify (OAuth). Якщо вікно не з'явилось, виконай `/mcp` і авторизуй `feededify-admin`.
- **Без MCP** обидва скіли працюють у ручному режимі: ти даєш агенту URL вихідного фіду (або файл експорту) і сам вставляєш промпти в Prompt Studio. Для авто-тюну MCP потрібен.
- **Codex та інші агенти:** додай MCP-сервер вручну в налаштуваннях агента за адресою `https://mcp.feededify.app/mcp` (HTTP).

## Аудит фіду

Почни з нього, коли не знаєш, які поля оптимізувати. Агент зчитує налаштування фіду (через MCP) або просить URL вихідного фіду, профілює товари, перевіряє поточні промпти й відповідає:
факти про фід, таблиця рекомендованих полів (навіщо, які є дані, які ризики), чернетки промптів і таблиця `product_type` → мітка для класифікаторів на кшталт `custom_label_N`. Нічого не зберігається. Наприкінці два шляхи: вставити промпти в Prompt Studio самому або запустити авто-тюн.

Дані клієнтів у чат не потрапляють: агент називає лише кількості й узагальнені описи, а вибірки тримає в тимчасовій теці.

## Авто-тюн

Потрібен admin MCP. Агент налаштовує промпти **на фіді, який ти назвеш**, орієнтуючись на реальний результат:

1. Читає фід, історію запусків і поточні промпти (лише читання).
2. Показує план: які поля змінить, їхні поточні промпти, до 3 ітерацій і оцінку вартості (за останнім повним запуском фіду).
3. Ти відповідаєш **«так»** (yes). Ця одна згода покриває всі збереження промптів і запуски фіду в цій сесії, до **3 ітерацій**. Будь-яка інша відповідь залишає ручний режим.
4. Кожна ітерація: чернетка або правка промптів, лінт, збереження, запуск фіду, очікування завершення, потім перевірка згенерованих значень за вихідними даними (ліміти, дозволені значення, втрачені чи вигадані факти) і розбір позначених рядків.
5. Зупиняється, коли реальних дефектів не лишилось, після 3-ї ітерації, коли вичерпано бюджет, якщо запуск завершився помилкою або якщо збереження зачепило б поле поза погодженим списком (тоді нічого не зберігає й питає).

Безпека:
- Змінюються лише названі тобою поля. Усі інші промпти лишаються як є, а якщо хтось тим часом відредагує одне з твоїх полів, агент зупиниться й спитає.
- Збереження перегенеровує змінені поля **для всіх товарів** фіду. Вартість показується наперед, а фактична береться з історії запусків.
- Агент веде найкращу версію **кожного поля** окремо (початкові промпти теж рахуються); новіша версія вважається кращою, лише якщо виправляє щонайменше на 2 рядки більше. Якщо ітерація вийшла гіршою, а також наприкінці, він одним збереженням ставить кожному полю його найкращу версію і зупиняється. Це змінює лише збережені промпти: поля, чий промпт змінився, лишаються з гіршим результатом до наступного запуску. Агент назве ці поля й запропонує один перезапуск із його вартістю.
- У фінальному звіті: остаточний промпт кожного поля, з якої він ітерації, загальна вартість і що ще не проходить.

## Як користуватись вручну

**1. Дай агенту контекст фіду:**
- назву поля та мету («нове поле `material_short`, до 30 символів, для оверлеїв на банерах»);
- **Source attributes** і **мову** фіду (форма редагування фіду);
- 3–5 прикладів товарів **з різних категорій** (вкладка Products);
- якщо виправляєш поле: його поточний промпт і кілька поганих результатів.

**2. Отримай промпт.** Агент поверне назву поля, тип і текст промпту, перевірений на твоїх прикладах.

**3. Протестуй і збережи в Prompt Studio:**
1. Products → **Edit prompts** → додай або відкрий поле → встав промпт.
2. **Test draft prompts** на 3–5 товарах, краще не з тих, що були в прикладах.
3. Якщо щось не так, скинь результати агенту.
4. **Save.** Збереження перегенеровує це поле для **всіх** товарів фіду на наступному запуску.

## Приклади запитів

- «Проаудитуй optimized feed `<id>` і скажи, які поля оптимізувати.»
- «Авто-тюн для title і size на фіді `<id>`.»
- «Напиши промпт для material за цими товарами: 1) … 2) … 3) …» (ручний режим)
- «Додай поле `material_short`: основний матеріал, до 30 символів, для банерів. Source attributes: title, description, product_type, brand. Мова uk. Товари: 1) … 2) … 3) …»
- «Тайтли задовгі й часто починаються з назви магазину. Поточний промпт title: … Погані результати: …»
- «Додай `product_highlight`: 3–6 коротких фактів про товар для Google Shopping.»
- «Додай `custom_label_0` для поділу кампаній за групами: yoga, fitness equipment, balls, accessories, other.»
- «Перевір усі наші збережені промпти: …»

## Правила

- Порожнє значення позначається як `""`. Ніколи не пиши «return null» чи «N/A», бо це слово потрапить у фід.
- Колонки називай точно як у Source attributes. Плейсхолдерів `{{…}}` немає.
- Для кожного поля вказуй ліміт: символи або кількість пунктів.
- Мову виходу задає налаштування фіду. Якщо дані джерела іншою мовою (наприклад, російською у фіді `uk`), скажи про це агенту, і промпт попросить перекладати.
- Для `google_product_category` промпт не потрібен, тип ставиться окремо.
